# ESP32-S3 智能发酵罐使用指南

本文主要说明保留的本地操作；Wi-Fi 接口版基线为 2026-10-21。适用对象：设备接线、实验操作和日常维护人员。配套文档：[代码架构](代码架构.md)、[主工程说明](../README.md)。

本指南对应 DS18B20、模拟 pH 模块和 TSL2591 已合并的主工程，Arduino 入口为 [main.ino](../main.ino)，调度实现在 [src/app/fermenter_app.cpp](../src/app/fermenter_app.cpp)。常规监测包含温度、pH、相对光学衰减、温控和趋势报警，可通过本地网页操作，也可配置 MQTT。功能实现按模块归档在 `src/modules/`，应用配置位于 `src/config/`，共享状态与数学工具位于 `src/shared/`。此前构建记录见文末；本次目录重组后需要重新构建确认，且整机、传感器精度、真实网络通信与生物学判据仍待实测。

## 1. 第一次使用的顺序

```mermaid
flowchart LR
    A[确认模块与接线] --> B[编译并烧录主固件]
    B --> C[串口查看热点与状态]
    C --> D[连接网页]
    D --> E[pH 两点标定]
    E --> F[纯培养基光学空白标定]
    F --> G[检查温度与数据记录]
    G --> H[按实验需要启用温控]
```

初次调试先完成传感器读取，再连接加热负载。日常重新上电时，完整标定和温度目标会恢复，自动加热需要重新启用。

## 2. 接线与准备

准备 ESP32-S3 开发板、USB 数据线、DS18B20、pH 调理板及 BNC 电极、TSL2591 模块、测量 LED 和驱动电路，以及实际参考值已知的 pH 缓冲液与培养基空白。光路应固定、遮光，并尽量避开气泡。

| 接口 | 默认连接 | 操作要点 |
|---|---|---|
| pH 模块电源 | 稳定 5 V 与 GND | 按实物丝印识别电源和地 |
| pH 模拟输出 S/AO/Po | 分压后接 GPIO1，ADC1 | 使用下方分压接法；玻璃电极先接调理板 BNC |
| DS18B20 DATA | GPIO4 | DATA 与 3.3 V 之间接 4.7 kΩ 上拉，采用三线供电 |
| TSL2591 VIN/VCC | 3.3 V | 使用支持该供电的模块，I²C 上拉到 3.3 V |
| TSL2591 SDA/SCL | GPIO8/GPIO9 | 默认地址 0x29，INT 无需连接 |
| 测量 LED 驱动输入 | GPIO5 | GPIO 控制晶体管或 MOSFET，LED 独立限流 |
| 加热继电器输入 | GPIO6 | 当前默认高电平有效，实际电平需与模块一致 |
| 蜂鸣器驱动输入 | GPIO7 | 当前默认高电平有效，根据负载采用适当驱动 |
| 低压参考地 | 各模块 GND 与主控 GND | 加热负载电流使用独立的合适线径 |

pH 模拟输出的默认接法：

```text
pH 模块 AO ---- 10 kΩ ----+---- GPIO1
                         |
                        10 kΩ
                         |
                        GND

GPIO1 --------- 100 nF -------- GND
```

两只电阻相等时，5 V 输出被分为约 2.5 V。代码按 `PH_DIVIDER_RATIO=2.0` 还原模块电压。先用万用表检查分压节点，再接主控；5 V 信号不能直接进入 ESP32 GPIO。

pH 说明资料展示过不同版本的板卡，接口排列应以实物丝印为准。多针板的数字阈值输出 Do 与模拟 pH 输出不是同一接口，本工程读取模拟输出。

引脚、输出有效电平和采样参数统一在 [fermenter_config.h](../src/config/fermenter_config.h) 修改。TSL2591 的模块供电、I²C 和固定地址可对照 [Adafruit 引脚说明](https://learn.adafruit.com/adafruit-tsl2591/pinouts)。

## 3. Arduino IDE 编译、烧录与串口

### 3.1 安装 ESP32 开发板包

使用 Arduino IDE 2.x。在“文件 → 首选项 → 附加开发板管理器网址”填入官方稳定版索引：

```text
https://espressif.github.io/arduino-esp32/package_esp32_index.json
```

打开开发板管理器，搜索并安装 **esp32 by Espressif Systems**，本工程配套构建版本为 **3.3.8**。具体安装步骤和国内下载镜像见 [Espressif 官方安装说明](https://docs.espressif.com/projects/arduino-esp32/en/latest/installing.html)。

### 3.2 安装传感器与通信库

在“工具 → 管理库”搜索下列库。遇到 Adafruit 依赖提示时选择安装所有依赖。

| 库管理器名称 | 配套版本 | 用途 |
|---|---|---|
| Adafruit TSL2591 Library | 1.4.5 | 光传感器 |
| Adafruit Unified Sensor | 1.1.15 | Adafruit 传感器接口 |
| Adafruit BusIO | 1.17.4 | Adafruit 总线依赖 |
| DallasTemperature | 4.0.x | DS18B20 温度 |
| OneWire | 2.3.8 | DS18B20 单总线 |
| PubSubClient | 2.8 | MQTT 客户端 |
| ArduinoJson | **6.21.6** | MQTT JSON 编解码 |

ArduinoJson 请在版本下拉框选择 6.21.6；表中的构建基线使用 6.x API。`WiFi`、`WebServer`、`WiFiClientSecure`、`Wire` 和 `Preferences` 来自 ESP32 开发板包，无需另装同名第三方库。即使暂时不使用 MQTT，通信模块仍参与编译，因此 PubSubClient 和 ArduinoJson 也要安装。

Arduino IDE 与 PlatformIO 使用独立的库目录。工程内部 `.pio/libdeps` 中已经下载的库，不会自动成为 Arduino IDE 的已安装库。出现 `DallasTemperature.h: No such file or directory` 等报错时，应在 Arduino IDE 的库管理器中安装对应依赖，或将完整库文件夹安装到该 IDE 草图目录下的 `libraries` 中。

### 3.3 打开主工程与选择开发板

打开本目录的 **main.ino**。保留 `main` 草图文件夹和整个 `src` 子目录；复制工程时复制整个 `main` 文件夹。Arduino 要求主 `.ino` 与所在草图文件夹同名，会递归编译 `src` 内的 C++ 模块。[Arduino 草图规范](https://docs.arduino.cc/arduino-cli/sketch-specification/)

当前交付仅包含主固件，原独立示例未复制。请上传本目录的 `main.ino`。

在“工具”菜单中选择以下配置。下表以 **8 MB Flash、未启用 PSRAM** 的 ESP32-S3 板为例；Flash/PSRAM 必须对照实物型号。

| 选项 | 设置 |
|---|---|
| Board | **ESP32S3 Dev Module**，来自 Espressif 的 esp32 包 |
| Port | 实际 ESP32-S3 的 COM 口 |
| Flash Size | 8MB (64Mb)，按实际 Flash 容量调整 |
| Partition Scheme | **8M with spiffs (3MB APP/1.5MB SPIFFS)**，适用于上面的 8 MB 板卡 |
| PSRAM | Disabled；本工程无需 PSRAM |
| Erase All Flash Before Sketch Upload | Disabled，保留已保存的设备设置 |
| USB Mode | Hardware CDC and JTAG |
| Upload Mode | UART0 / Hardware CDC |
| USB CDC On Boot | USB 转串口桥选 Disabled；原生 USB 口选 Enabled |
| Upload Speed | 可先用 460800；通信不稳定时改 115200 |

4 MB Flash 板卡应选择实际 4 MB 容量及足够的程序分区，例如 Huge APP，不能照用 8 MB 分区表。其他设置保留开发板默认值。菜单含义见 [Espressif 工具菜单说明](https://docs.espressif.com/projects/arduino-esp32/en/latest/guides/tools_menu.html)。

`src/config/fermenter_config.h` 和 `src/config/mqtt_config.h` 用于修改接线与联网设置，可在 Arduino IDE 的草图文件列表中展开 `src/config` 找到。

### 3.4 编译与上传

1. 点击“验证/编译”，首次构建会较慢。
2. 关闭占用该 COM 口的其他串口工具，点击“上传”。
3. 如停在 Connecting，可按住 BOOT，短按 RESET/EN 后松开 RESET，再在连接开始时松开 BOOT；上传完成后按需按 RESET 运行。
4. 打开串口监视器，设置 **115200 baud** 和换行或回车换行。

默认输出为 UART/USB 转串口桥；使用原生 USB 时务必启用上面的 CDC 选项。原生 USB 重启后端口可能重新枚举，需要重新选择 COM 口。发送命令使用半角字符；串口每行最多处理 63 字符。

正常启动会输出 pH 标定加载情况、TSL2591 状态、热点名称与密码，以及 CSV 表头和命令提示。没有配置 MQTT 时看到 `MQTT disabled` 属于预期状态，本地采集和网页仍可运行。TSL2591 未找到时，约每 5 秒重试；温度和 pH 仍继续采集。

### 3.5 保留的 PlatformIO 入口

本次改动以 Arduino IDE 和 ESP32 Arduino 3.3.8 为构建入口。`platformio.ini` 仅作为旧配置参考，其默认平台可能使用 Arduino 2.x；迁移时需先匹配开发板包版本。

```text
pio run -e esp32-s3-devkitc-1
pio run -e esp32-s3-devkitc-1 -t upload
pio device monitor -b 115200
```

## 4. 连接网页与配置 Wi-Fi

1. 在串口找到 `Fermenter-S3-xxxxxx` 热点名称和生成的密码。
2. 手机或电脑连接设备热点；若提示没有互联网，选择保持连接。
3. 打开 `http://192.168.4.1`，用户名为 `admin`，密码与串口显示的设备网页密码一致。
4. 在“路由器 Wi-Fi”表单中填写实验室 Wi-Fi 名称与密码，保存后等待连接。
5. 连接成功时，串口和网页会显示路由器分配的设备 IP。处于同一局域网的设备可通过该 IP 访问。

设备热点与路由器连接并行保留。路由器断开时，可以回到设备热点操作。网页采用本地 HTTP 和登录验证，应在可信网络中使用。

网页约 **2.5 秒刷新一次**，常规采样约 **5 秒一次**，所以连续两次刷新可能显示同一组数据。

忘记密码或需重新配网时，通过串口发送 `WIFI_RESET`。它会清除路由器凭据并轮换热点/网页登录密码，新密码会从串口显示；pH 标定、光学空白和温度目标继续保留。

## 5. pH 两点标定

### 5.1 标定前

按电极厂家要求完成活化和准备。使用两种实际参考 pH 已知的缓冲液，按标签对应温度的数值填写；例如 6.86 与 7.00 应分别使用其真实参考值。固定模块供电、分压、电位器和接线条件。

同一次标定由同一位操作者连续完成，期间避免其他网页、串口或 MQTT 客户端交叉发送标定指令。

### 5.2 网页操作

1. 电极放入第一种缓冲液，至少等待约一分钟，并观察信号稳定。
2. 在“当前缓冲液的参考 pH”填写实际数值，例如 `7.00`，点击“记录第一个点”。
3. 清洗并移入另一种缓冲液，等读数稳定。
4. 将输入框改为第二种缓冲液的实际值，例如 `4.00`，点击“记录第二个点”。
5. 确认显示两点标定已完成并保存，再回测缓冲液或使用第三种已知样品检查。

### 5.3 串口操作

每行单独发送，换缓冲液和等待稳定的步骤在两条命令之间完成：

```text
PHCAL 7.00
PHCAL 4.00
STATUS
```

偏碱工作范围可选择合适的另一种缓冲液，例如参考值为 9.18 的标准液；按实际标签填写。软件要求两点参考 pH 相差至少 0.5、模块输出电压相差至少 50 mV，否则拒绝第二点。

### 5.4 状态与重新标定

| 状态 | 含义与下一步 |
|---|---|
| pH 显示 `--` / 串口 `nan` | 可能未标定或当前电压/换算无效，检查状态字段 |
| 已记录第一点 | 第一参考值和电压保存在内存，继续采第二点 |
| 第二点失败 | 第一点和旧的完整标定保留，检查后重试第二点 |
| 完整标定成功 | 新系数保存并开始使用，重启可恢复 |
| 已有标定，同时正在重标定 | 新的第二点成功前，显示值仍可来自旧系数 |

`PHRESET` 或网页“清除 pH 标定”清除完整标定及未完成的第一点。第一点不会跨重启保存。调电位器、更换电极、模块、分压或接线后应重新标定。

程序没有自动温度补偿，`phVoltageValid` 也不能可靠判断玻璃电极是否脱落。应通过标准样品检查实际测量质量。

## 6. 光学空白标定与报警

### 6.1 保存培养基空白

1. 固定 LED、传感器、光程与遮光结构，放入与实验一致的纯培养基空白。
2. 网页点击“标定纯培养基空白”，或串口发送 `CAL`（也支持 `BLANK`）。
3. 保持光路稳定，等待 10 组有效测量完成；网页会显示进度，串口成功信息包含 `blank_counts=... saved`。
4. 再开始样品测量。改变光源、增益、积分时间、光路或培养基后重新标定。

空白标定期间，温度与 pH 仍按主循环采集，温控继续运行，光学趋势暂时暂停。出现传感器缺失、饱和或低信号时，本次标定失败并保留旧空白。若日志包含 `RAM only`，说明新空白仅在本次运行内有效，存储问题处理后应重新保存。

`BLANKRESET` 可以取消正在进行的空白标定并清除空白值；此后需重新 `CAL` 才能计算相对衰减。

### 6.2 理解光学值

```text
净光强 I = LED 点亮 CH0 平均值 - LED 熄灭 CH0 平均值
相对衰减 A* = -log10(I / I0)
```

`I0` 是保存的空白净光强。`od_proxy` 表示上述相对衰减，尚需与目标样品的参考 OD600 建立标定关系。`lux` 是照度估计，不参与相对衰减计算。

样品比空白透光更强时，可能出现负的 `od_proxy`，可以据此检查空白、光源漂移或样品差异。未积累足够有效数据时，斜率显示为空；趋势拟合需要 12 次有效采样，标称约一分钟。

### 6.3 报警后的操作

默认算法对光学指标做三点平滑，再用十二个平滑值计算趋势；斜率连续 36 次不高于 `-0.010/min` 时锁定蜂鸣器报警。相对衰减下降对应透射光增强，报警后应结合取样、离线测量和实验现象复核。

网页点击“复位报警”或串口发送 `RESET`，会关闭锁定报警并清空趋势窗口。光学标定或无效采样会清空窗口，但不会自行解除已锁定的报警。

## 7. 温控、日常运行与结束实验

默认目标温度为 30 ℃，回差为 ±0.5 ℃。满足加热条件时，温度不高于 29.5 ℃开启，达到 30.5 ℃关闭。网页可设置目标温度并勾选“启用自动加热”，保存后生效。

当前网页输入范围为 5～39 ℃；底层接口要求 `5 ≤ 目标温度 < 39.5 ℃`。软件过温上限为 40 ℃。

| 条件 | 当前程序行为 |
|---|---|
| 重新上电 | 自动加热关闭，恢复保存的温度目标 |
| 温度无效或达到 40 ℃ | 执行温控检查时关闭继电器 |
| 温度样本超过 15 秒未更新 | 下一次温控检查时关闭继电器 |
| pH 或光学数据无效 | 对应测量结果无效，温控仍根据温度运行 |
| 路由器或 MQTT 断开 | 本地温控按当前设置继续运行 |
| 取消启用自动加热并保存 | 关闭继电器，等待再次人工启用 |

过温、故障或过期检查不会把 `heaterEnabled` 自动改为关闭状态；条件恢复后，启用中的自动温控可能再次加热。需要持续停止加热时，应取消启用并保存。软件调用存在采样与通信阻塞，独立硬件过温保护和实测故障响应仍然必要。

日常运行时记录培养基、样品、光路设置、标定时间、搅拌和人工操作。结束实验先关闭自动加热并确认继电器关闭，保存数据，再断电；电极清洗和保存按其厂家要求执行。

## 8. 串口命令速查

| 命令 | 作用 | 不会自动执行的操作 |
|---|---|---|
| `PHCAL <参考 pH>` | 采第一点或用第二点完成 pH 标定 | 不自动等待电极稳定 |
| `PHRESET` | 清除完整和未完成的 pH 标定 | 不停止温控 |
| `CAL` / `BLANK` | 启动 10 组光学空白标定 | 不清除锁定报警 |
| `BLANKRESET` | 取消空白标定并清空白值、趋势 | 不清除锁定报警 |
| `RESET` | 清除锁定报警和趋势 | 不关闭自动加热 |
| `STATUS` | 输出当前传感器、标定与控制状态 | 不修改设置 |
| `WIFI_RESET` | 清路由器配置并轮换热点/网页密码 | 不清除 pH、空白和温度目标 |
| `HELP` | 显示命令 | 不修改设置 |

## 9. 记录数据与解释空值

串口约每 5 秒输出一行 CSV。设备没有自动创建历史文件，可使用串口工具保存日志，再整理为 CSV。启动表头以 `# millis,...` 开头，整理时去掉该表头的 `# ` 前缀；其余 `#` 提示行不属于数据。

```text
millis,temp_C,light_counts,od_proxy,slope_per_min,optical_valid,heater_on,lysis_alarm,ph,ph_adc_mV,ph_module_mV,ph_voltage_valid,ph_calibrated,ph_valid,full_counts,ir_counts,dark_counts,lux,calibration_running
```

| 列 | 含义与单位 |
|---|---|
| `millis` | 本行输出时设备启动后的毫秒数，重启后重新计时 |
| `temp_C` | 温度，℃ |
| `light_counts` | LED 开/关差分净光强，counts |
| `od_proxy` | 相对光学衰减，无量纲 |
| `slope_per_min` | 相对衰减每分钟的变化量 |
| `optical_valid` | 光学结果有效标志，0/1；为 0 时不应使用相应光学结果 |
| `heater_on` / `lysis_alarm` | 继电器输出状态 / 锁定报警状态，0/1 |
| `ph` | 当前标定换算后的 pH |
| `ph_adc_mV` / `ph_module_mV` | GPIO1 电压 / 按分压比例还原的模块电压，mV |
| `ph_voltage_valid` | ADC 电压在程序设置的可用范围内 |
| `ph_calibrated` / `ph_valid` | 有有效系数 / 当前有可用 pH 结果，0/1 |
| `full_counts` / `ir_counts` | LED 点亮时 CH0 / CH1 平均计数 |
| `dark_counts` | LED 熄灭时 CH0 平均计数 |
| `lux` | LED 点亮时照度估计，lx |
| `calibration_running` | 光学空白标定正在运行，0/1 |

前 8 列保留原有顺序，合并后追加至共 19 列。固定列数的后处理脚本需要按新表头读取。设备内部无效浮点值使用 `NAN`，串口显示 `nan`，网页显示 `--`，JSON 通常为 `null`。

## 10. MQTT 联网操作

### 10.1 配置设备

在 [mqtt_config.h](../src/config/mqtt_config.h) 填写 `DEVICE_ID`、`BROKER_HOST`、`BROKER_PORT`、`USERNAME`、`PASSWORD` 和 `ROOT_CA`。主机名填写域名或主机地址，不带 `mqtt://` 或 `https://`；默认 TLS 端口为 8883，需与 Broker 设置一致。

根证书填写完整的受信任根 CA PEM，包括 BEGIN/END 行。设备保留 TLS 证书校验；Broker 和 CA 未配置时 MQTT 关闭。每台设备使用唯一 ID，并为凭据设置合适的主题权限；真实凭据不要放入公开仓库。

设备连接路由器并具备有效时钟后才尝试连接 Broker。时钟尚无效时会请求 NTP，约每分钟重试。启动日志 `MQTT connected; subscribed to command topic` 表示已连接并发出了命令主题订阅请求，实际通信仍应通过遥测和命令回执检查。

### 10.2 订阅与发布

默认 `DEVICE_ID=fermenter-01` 时：

| 主题 | 用途 |
|---|---|
| `igem/fermenter/fermenter-01/telemetry` | 订阅温度、pH、光学和控制状态，约每 5 秒发布 |
| `igem/fermenter/fermenter-01/availability` | 订阅保留的在线状态，异常掉线由遗嘱更新 |
| `igem/fermenter/fermenter-01/cmd` | 控制端发布命令，建议 QoS 1、关闭 retained |
| `igem/fermenter/fermenter-01/ack` | 订阅命令执行回执 |

遥测中的 `timestamp` 是发布时的 Unix 秒数，和 CSV 的启动毫秒数用途不同。`phCalibrated` 表示系数存在，`phValid` 表示当前 pH 可用，`phCalibrationPending` 表示已采第一点。

下面在 PowerShell 中生成一条带当前时间的新命令，再将输出 JSON 粘贴到 MQTT 客户端的 `cmd` 主题发送：

```powershell
$message = [ordered]@{
  id = [guid]::NewGuid().ToString()
  type = 'calibrate_ph'
  value = 7.00
  issuedAt = [DateTimeOffset]::UtcNow.ToUnixTimeSeconds()
}
$message | ConvertTo-Json -Compress
```

第一缓冲液稳定后发送上面的命令。第二缓冲液稳定后，将 `value` 改为实际参考值，重新生成新 ID 和时间后发送。每条命令的 ID 最多 64 字节，超过 120 秒或来自未来超过 30 秒的命令会被拒绝。

| `type` | `value` 与作用 |
|---|---|
| `calibrate_ph` | 数值，当前缓冲液参考 pH |
| `reset_ph_calibration` | 无需 value，清除 pH 标定 |
| `calibrate_blank` | 无需 value，排队光学空白标定 |
| `reset_blank` | 无需 value，取消/清除光学空白 |
| `set_target` | 数值，温度目标 |
| `heater_enable` | JSON 布尔值 `true` / `false`，启停自动温控 |
| `reset_alarm` | 无需 value，复位报警 |

控制端应等到同一 `id` 的 `ack` 并检查 `ok`、`message`，再核对遥测。光学标定的成功回执表示已排队，完成情况还需查看进度和空白值。

遥测和回执采用 QoS 0。超时后可在有效时间内重发同一条命令，保留同一 ID 和内容；设备缓存本次启动内最近 8 条结果，命中时标记 `duplicate=true` 并返回原结果。新操作应使用新 ID，失败后修改命令内容也应使用新 ID。缓存不跨重启保存，在线状态和回执均不能作为即时加热急停保障。

## 11. 常见问题

| 现象 | 先检查什么 |
|---|---|
| 无法上传或串口无输出 | USB 数据线、实际端口、端口占用、USB 转串口与原生 USB 的配置是否匹配 |
| 编译提示找不到某个库的 `.h` 文件 | 安装第 3.2 节列出的全部库，并确认 ArduinoJson 选择 6.21.6 |
| Windows 提示 `Assembler ... can't create ... No such file or directory` | 检查临时构建路径是否含中文；使用英文临时目录，必要时将整个草图复制至如 `C:\ArduinoProjects\firmware` 的英文目录 |
| 连接热点后打不开网页 | 是否保持连接无互联网热点、地址是否为 `192.168.4.1`、浏览器是否使用 HTTP |
| 网页登录失败 | 用户名 `admin`，使用串口最新密码；若执行过 `WIFI_RESET`，旧密码已失效 |
| 路由器一直连不上 | Wi-Fi 名称与密码、2.4 GHz 网络、信号和接入策略；可先回到设备热点操作 |
| 温度为 `nan` | DS18B20 供电、共地、GPIO4 与 4.7 kΩ 上拉；自动加热会因温度无效而关闭 |
| pH 一直为 `nan` | 分别检查 `ph_calibrated`、`ph_voltage_valid`、模块电压和两点标定是否完成 |
| pH 第二点被拒绝 | 是否仍填写第一缓冲液的值、信号是否稳定、两种缓冲液与电压是否确有差别 |
| 光学空白失败 | TSL2591 接线、LED 驱动、遮光、低信号或饱和；不能只接收光器而缺少测量光源 |
| 标定后斜率仍为空 | 等待累积 12 次有效采样；光学失效会重新开始积累 |
| 蜂鸣器持续报警 | 先复核实验和光路，再执行 `RESET`；重新标定不会自动解除报警 |
| 开启温控但不加热 | 温度是否已达到目标、是否无效/过期/过温、继电器有效电平是否匹配 |
| MQTT 显示 disabled | Broker 主机与根 CA 是否完整配置；本地网页不依赖 Broker |
| MQTT 长时间未连接 | 路由器互联网、NTP、主机名、TLS 端口、证书链、账号与主题权限 |
| 断电后 pH 或空白设置不符预期 | 是否真正完成保存；检查 `RAM only` 或 NVS 保存失败日志 |

串口 MQTT 连接状态码：`-4` 超时、`-3` 连接丢失、`-2` 连接失败、`-1` 未连接、`0` 已连接、`1` 协议不接受、`2` 客户端 ID 不接受、`3` 服务不可用、`4` 凭据错误、`5` 未授权。连接失败不一定能仅靠一个状态码判断证书或网络问题，需结合日志。
